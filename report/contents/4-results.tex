\section{РЕЗУЛЬТАТЫ РАБОТЫ}

\iffalse
Требования к симулятору
- продвижение агентов
- выдача новых точек назначения
- построение маршрутов
- ....

Перемещение агентов
- перемещаются с текущей скоростью на dt
- более сложный вариант - не врезаются во вперед едущих агентов
  (несколько агентов не могут ехать в одной точке в одном направлении)

Агенты
- привязаны к координатам: 
  для операций с ребрами надо мапить на ребра
  для операций с другими агентами и визуализации ничего не надо делать
- привязаны к ребрам:
  для операций с ребрами ничего не надо делать
  для операций с агентами и визуализации надо вычислить координаты
- храним и долю пройденного текущего ребра и координаты
  маршрут - список ребер, каждое ребро хранит координаты и длину
  route follower ???

Граф
- вершины и ребра не изменяются
- свойства вершин и ребер не изменяются
-> продвигаться по маршруту можно не сверясь с графом

Изменения состояния агентов:
- инкапсулированы в агентах
- вынесены в отдельные классы/методы, которые изменяют всех агентов

Структура графа
- вершины
    - id
    - координаты
- ребра
    - длина
    - ...

Агенты могут начинать и завершать маршрут только в вершинах графа
Некоторые вершины графа представляют из себя точки доставки, некоторые -- базовые точки
Каждый агент привязан к одной базовой точке и не меняет ее в ходе симуляции
Агент может получить новый маршрут только когда он находится на базовой точке
Агент перемещается от базовой точки до точки доставки, затем возвращается на базовую точку
Маршрут агента вычисляется тогда, когда он необходим

Агенты каким-то образом распределяются по базовым точкам (равномерно??, по числу точек доставки в округе??)
Диспатч отслеживает состояние агентов и выдает им новые заказы, запрашивает маршруты для этих заказов и передает их агентам
Диспатч как-то выбирает точку доставки, в первом приближении случайную, во втором -- распределить точки доставки по базовым точкам по близости (евклидовой или по графу)
Диспатчу надо либо запоминать на каком этапе агент (чтобы отправить его обратно по достижении цели), ~~~либо получать эту информацию из состояния агента (состояния perform_order, finish_order, return_to_base)~~~
Диспатч хранит текущую точку доставки
